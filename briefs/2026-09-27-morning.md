## Tools worth touching

### Hindsight
- Does: open-source agent memory layer that learns from interaction history instead of relying on static RAG retrieval
- Why now: today's top-trending GitHub repo, up roughly 4,460 stars in a day
- Try if: you're building a long-running agent that needs to remember past sessions without re-embedding everything each time
- Skip if: your agent is stateless or single-turn, this is pure overhead
- Links: [repo](https://github.com/vectorize-io/hindsight)

### OpenRig
- Does: a multi-agent harness that runs [[claude-code]] and [[codex]] side by side as one coordinated system
- Why now: a direct, practical answer to "which coding agent do I use" — route or compare work across both instead of picking one
- Try if: you already script Claude Code or Codex and want a shared harness instead of maintaining two separate setups
- Skip if: you only use one coding agent and have no need to compare or route between them
- Links: [repo](https://github.com/mvschwarz/openrig)

### Paperclip
- Does: open-source app for managing a fleet of AI agents at work — task assignment and tracking across agents
- Why now: one of today's fastest-growing repos, a signal of real demand for agent-ops tooling beyond single-agent chat
- Try if: your team runs more than a couple of agents and needs a shared dashboard rather than ad-hoc scripts
- Skip if: you're a solo dev running one agent, this is unnecessary process overhead
- Links: [repo](https://github.com/paperclipai/paperclip)

### Univer
- Does: an "office harness for AI agents" — a structured runtime for agents to manipulate spreadsheets, docs, slides, and relational tables
- Why now: trending today as agent frameworks start targeting structured office documents instead of generic file I/O
- Try if: your agent needs to reliably edit spreadsheets or slide decks, not just read them
- Skip if: your agent's output is plain text or markdown, this adds complexity you don't need
- Links: [repo](https://github.com/dream-num/univer)

### NVIDIA Model Optimizer
- Does: [[nvidia]]'s own toolkit for quantization, distillation, and pruning to cut inference cost
- Why now: picked up meaningful trending traction today as teams look to shrink inference bills
- Try if: you're serving a model in production and haven't run a quantization pass yet
- Skip if: you already have a mature quantization pipeline (AWQ, bitsandbytes, etc.) covering your target hardware
- Links: [repo](https://github.com/NVIDIA/Model-Optimizer)
