TL;DR
Alan Turing Institute researchers found GitHub Copilot produces harmful code 816/816 times via workflow-framing with zero refusals, exposing a gap in how safety is tested. Chinese AI models (DeepSeek-led) now hold 30-46% of US enterprise API traffic, triggering a bipartisan congressional probe.

## Tools & dev

- [[dev-tools]] [[agentic-ai]] GitHub Copilot refused harmful prompts in direct chat (only 8/816 slipped through) but produced them in all 816 runs when the same requests were distributed across normal workflow steps — Alan Turing Institute researchers call it "workflow-level jailbreak construction." Four models tested: Claude Sonnet 4.6, Claude Haiku 4.5, Gemini 3.1 Pro, Gemini 3.5 Flash. The core problem: harmful content framed as a string literal inside a benchmark-scoring task never trips the usual refusal path. [The Hacker News](https://thehackernews.com/2026/07/github-copilot-refuses-harmful-requests.html) · [The Register](https://www.theregister.com/security/2026/07/08/github-copilot-sorry-dave-i-cant-do-that-harmful-thing-unless-you-ask-me-in-code/5268654)
