## The signal

1. **MCP 2026-07-28 spec ships today: stateless core, Tasks, MCP Apps**
   What happened: The Model Context Protocol final spec (and release candidate) landed today, dropping the initialize handshake and Mcp-Session-Id entirely, redesigning Tasks as a first-class async extension, adding MCP Apps for interactive HTML UIs rendered inline in clients over the same JSON-RPC path, and hardening auth with six security enhancements (including iss field validation per RFC 9207).
   Why it matters: Any existing MCP server using the session handshake needs migration; Tasks and MCP Apps unlock async work patterns and rich UI that agent frameworks will start building on immediately.
   Confidence: Confirmed
   Sources: [MCP Blog](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/) (primary) · [WorkOS auth analysis](https://workos.com/blog/mcp-2026-spec-agent-authentication) (independent) · [AAIF migration guide](https://aaif.io/blog/mcp-2026-07-28-whats-changing-and-how-to-migrate) (independent)

2. **Kimi K3 weights live: 594GB MXFP4, vLLM day-0 KDA, llama.cpp still pending**
   What happened: Moonshot AI dropped Kimi K3 weights on Hugging Face on July 26 (one day ahead of the July 27 target). Together AI and Modal had day-0 cloud hosting. vLLM shipped full KDA (Kimi Delta Attention) support with fused decode, MXFP4 MoE execution, and prefix caching. llama.cpp has early community groundwork but KDA kernels are not yet merged.
   Why it matters: The largest open-weight model ever (2.8T params, ~50B active) is now self-hostable via vLLM on a real cluster; the llama.cpp gap means edge/desktop inference is weeks out at minimum.
   Confidence: Confirmed
   Sources: [Startup Fortune](https://startupfortune.com/moonshot-ai-releases-kimi-k3-open-weights-making-the-worlds-largest-open-weight-model-free-to-download/) (independent) · [vLLM day-0 blog](https://vllm.ai/blog/2026-07-27-k3) (primary) · [llama.cpp discussion](https://github.com/ggml-org/llama.cpp/discussions/26041) (community) · [[natolambert]] [open-weights escalation](https://www.interconnects.ai/p/kimi-k3-the-open-weights-escalation) (independent)

## Models & research

### Claude Opus 5
**Claim:** Matches Fable 5 performance on most benchmarks; priced at $5/$25 per million tokens (input/output); effort-level toggle (low/medium/high) trades cost for capability.
**Evidence:** Anthropic announcement; Axios and Fortune coverage confirm pricing and positioning. No independent benchmark leaderboard entry published as of this writing.
**Caveat:** "Matches Fable 5 on most tasks" is a company claim without a reproducible third-party eval. Benchmark coverage is selective until the community runs its own suites.
**Worth your time:** Read. If the performance claim holds up, this halves the cost of near-frontier reasoning. Test on your actual workloads before migrating. [Axios](https://www.axios.com/2026/07/24/anthropic-releases-new-model-opus-5)

### Kimi K3 open weights
**Claim:** 2.8T-parameter MoE (16-of-896 experts, ~50B active), 1M context, native vision, MXFP4 native quantization, open weights on Hugging Face (594GB download).
**Evidence:** Weights live on Hugging Face; vLLM day-0 KDA support confirmed with production performance numbers; Together AI and Modal hosting day-0. llama.cpp kernel work in community thread but not merged.
**Caveat:** MXFP4 is non-standard. Consumer and CPU inference is not viable yet. Full independent quality eval not yet published against the self-hosted weights.
**Worth your time:** Read. Pull from Together or Modal to evaluate; download only if you have the cluster. Watch llama.cpp#26041 for desktop inference ETA. [vLLM blog](https://vllm.ai/blog/2026-07-27-k3) · [Kimi blog](https://www.kimi.com/blog/kimi-k3)

## Tools worth touching

### MCP 2026-07-28 spec
- Does: New stateless MCP protocol -- no session ID, redesigned Tasks extension for async work, MCP Apps for inline HTML UIs, hardened auth
- Why now: Spec drops today; existing servers using Mcp-Session-Id need migration before clients adopt the new version
- Try if: You maintain any MCP server or build agent orchestration on MCP primitives
- Skip if: You are a pure MCP client consuming existing servers and have no server-side code
- Links: [spec RC](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/) · [migration guide](https://aaif.io/blog/mcp-2026-07-28-whats-changing-and-how-to-migrate) · [auth changes](https://workos.com/blog/mcp-2026-spec-agent-authentication)

### alibaba/open-code-review
- Does: LLM code review combining deterministic pipelines with LLM agents; produces line-level PR comments with built-in security rulesets; supports OpenAI and Anthropic backends
- Why now: 979 stars on GitHub trending today; drops between static analysis and pure LLM-only review
- Try if: You want automated security-aware code review on PRs without a hosted product dependency
- Skip if: You already have a mature code gate; Go-based setup has non-trivial config overhead for non-Go teams
- Links: [github.com/alibaba/open-code-review](https://github.com/alibaba/open-code-review)

### vLLM with Kimi K3 KDA support
- Does: Production-scale serving of Kimi K3 with native KDA prefix caching, fused decode kernels, and MXFP4 MoE execution
- Why now: Only viable self-hosted path to K3 right now; llama.cpp alternative is weeks out
- Try if: You run H100-class hardware and want to evaluate near-frontier open weights in a controlled environment
- Skip if: You lack the cluster footprint; consumer GPU stacks cannot run this yet
- Links: [vLLM day-0 blog](https://vllm.ai/blog/2026-07-27-k3) · [self-host guide](https://dev.to/lola_lin_a1be8395c517b081/kimi-k3-open-weights-are-here-how-to-self-host-the-28t-parameter-model-hardware-vllm-and-data-4b0n)
